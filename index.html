backupctl

Back up your sites' and microservices' databases — MySQL and PostgreSQL — in three commands.

$ curl -fsSL https://raw.githubusercontent.com/Solo-it/backupctl/main/backupctl-install.sh | sh

Detects apt or Homebrew and uses those; otherwise downloads the matching binary from the latest release and verifies it against checksums.txt. Nothing hidden — see backupctl-install.sh.

$ curl -fsSL https://solo-it.github.io/backupctl/apt/signing-key.asc | sudo gpg --dearmor -o /usr/share/keyrings/backupctl.gpg $ echo "deb [signed-by=/usr/share/keyrings/backupctl.gpg] https://solo-it.github.io/backupctl/apt stable main" | sudo tee /etc/apt/sources.list.d/backupctl.list $ sudo apt update && sudo apt install backupctl

Debian/Ubuntu. GPG-signed — see SECURITY.md.

$ brew install Solo-it/tap/backupctl

macOS/Linux. For the short brew install backupctl form afterwards: brew tap Solo-it/tap && brew trust solo-it/tap once.

$ go install github.com/Solo-it/backupctl/cmd/backupctl@latest

Builds from source, no binary download.

See the Releases page for .tar.gz/.zip binaries, .deb, .rpm and .apk packages.

What it does

Server → restic repository

Dumps MySQL/PostgreSQL on a schedule (UTC, explicit systemd timer), backs them up with restic, installs restic itself if missing.

Client pulls, never pushes

The client fetches the repository over rsync via SSH. The server's backup-user has no password at all — key-only, restricted to rsync.

Cross-platform clients

launchd and pm2 on macOS, systemd on Linux, Task Scheduler on Windows — same config format everywhere.

Idempotent by design

Re-run --init-server any time — adding a database means editing the config and running it again, nothing destructive.
